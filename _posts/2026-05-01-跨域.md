## 产生原因

**同源策略**是浏览器最核心、最基础的**安全机制**。它规定：**协议、域名、端口**三者完全相同的两个资源才属于**同源**。浏览器默认只允许页面访问**同源**的接口与资源，禁止非同源的 URL 之间进行资源的交互，以此防止恶意脚本窃取用户数据、攻击其他网站。

**协议、域名、端口**任意一项不同，即为跨域。跨域请求会被浏览器的同源策略拦截，导致请求无法正常获取数据，这就是**跨域问题**。

**同源策略是浏览器施加的安全限制，仅存在于浏览器环境中，并且只限制浏览器发出的 HTTP/HTTPS 请求！**

因此：

1. **跨域问题只会发生在前端（浏览器发起的请求）。**
2. **服务器与服务器之间的相互调用，不受同源策略限制，不存在跨域问题。**

## 解决方法

### CORS

在CORS中，将请求分为简单请求、非简单请求两种

简单请求： 只发送一次请求，同时把 "请求 + 数据" 发到后端，后端直接返回 "数据 + 响应头"

请求类型是以下三种之一

- HEAD
- GET
- POST

HTTP的头信息不超出以下几种字段

- Accept
- Accept-Language
- Content-Language
- Last-Event-ID
- Content-Type：只限于三个值 `application/x-www-form-urlencoded、multipart/form-data、text/plain`

在简单请求中，CORS会在头信息中增加一个字段：**Origin**,表示请求源域名

非简单请求：不是简单请求的都是非简单请求，非简单请求会在正式通信之前，增加一次HTTP查询请求，称为OPTIONS 预检请求（询问服务器是否允许跨域），服务器允许后，再发送真正的请求，一共 **2 次请求**，

非简单请求除了Origin字段，"预检"请求的头信息包括两个特殊字段：

Access-Control-Request-Method：用来列出浏览器的CORS请求会用到哪些HTTP方法（必选）

Access-Control-Request-Headers：是一个逗号分隔的字符串，指定浏览器CORS请求会额外发送的头信息字段（可选）

常见非简单请求如下：

请求方法是：PUT、DELETE、PATCH 等

Content-Type 为：`application/json`

包含自定义请求头：如 token、Authorization

```java
@Configuration
public class CorsConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
                .allowedOrigins("*")
                .allowedMethods("GET", "POST", "PUT", "DELETE")
                .allowedHeaders("*");
    }
}
```

### 前端代理

Vite / Webpack 自带代理，利用本地开发服务器做中间人转发请求，彻底绕过浏览器同源策略。

Vite 自己启动的本地开发服务器，达到"浏览器 → vite 服务器 → 后端"，浏览器只看到自己和 Vite 通信，不跨域；Vite 去请求 Java，服务端请求，不跨域。

```javascript
export default {
  server: {
    proxy: {
      "/api": {  // 匹配 以 /api 开头的请求
        target: "http://localhost:8080",  // 目标：转发到后端地址
        changeOrigin: true,  // 开启跨域：告诉后端"我是来自同源的请求"
        rewrite: (path) => path.replace(/^\/api/, "")  // 路径重写：把 /api 去掉
      }
    }
  }
}
```

请求链路：

```
前端请求：axios.get('/api/user')
          ↓
浏览器自动拼地址：http://localhost:5173/api/user
          ↓
请求先到达 Vite 服务器
          ↓
Vite 看：以 /api 开头 → 走代理
          ↓
转发给 Java：http://localhost:8080/user
          ↓
Java 返回数据给 Vite
          ↓
Vite 返回数据给浏览器
```

特点：

1.只在开发环境生效：proxy 是 Vite 提供的功能，不是 JS 代码，打包不会把它打进包里！运行`npm run dev` 时Vite 启动了一个本地服务器`localhost:5173` ，这个服务器自带代理功能；部署线上运行 `npm run build` 时Vite只会把代码编译成 纯静态文件（HTML、CSS、JS），没有服务器转发，代理功能直接报废

2.前端独立解决，无需后端处理

3.对浏览器完全透明，真正绕过同源策略

4.配置简单、使用方便

### Nginx 反向代理

Nginx和和 Vite 代理一模一样！前端、后端都不用改，nginx 统一转发，"浏览器 → 请求 Nginx（同源）→ 转发请求到后端"

Nginx → 返回数据给浏览器

```
location /api {
    proxy_pass http://localhost:8080;
    add_header Access-Control-Allow-Origin *;
}
```

优点：

1. 生产环境标准方案
2. 支持所有请求类型（GET/POST/PUT/DELETE）
3. 支持 application/json、自定义头
4. 浏览器无感知，完全不跨域
5. 高性能、稳定

缺点：

1. 需要运维 / 后端配置 Nginx
2. 不能在开发环境使用

代理跨域 = 绕开浏览器！无论是Vite、Nginx代理都是找了个中间服务器，把请求转发到后端

1. 浏览器不能直接请求后端（8080）→ 会跨域
2. 先请求中间服务器（Vite/Nginx）→ 同源，不拦截
3. 中间服务器去请求后端→ 无跨域，随便访问
4. 中间服务器把结果带回来给浏览器

### WebSocket

WebSocket一种全双工、长连接的网络通信协议，本身不受浏览器同源策略限制，天生支持跨域，不需要任何跨域配置！

- 可以客户端 → 服务端发消息
- 可以服务端 → 客户端主动推送消息
- 常用于聊天、实时通知、直播弹幕、实时数据大屏

```js
// 直接连接后端，不需要跨域配置
const ws = new WebSocket("ws://localhost:8080/ws");

ws.onopen = () => {
  console.log("连接成功！");
};

ws.onmessage = (evt) => {
  console.log("收到消息：", evt.data);
};
```

```java
@ServerEndpoint("/ws")
@Component
public class WebSocketServer {
    // 连接、收发消息
}
```

特点：

- 天生支持跨域，不需要配置 CORS、代理，HTTP/HTTPS 才有跨域，其余协议没有！
- 不受同源策略限制
- 全双工通信，服务端可主动推送
- 一次连接，永久通信，性能比 HTTP 好

### JSONP

JSONP = 利用 script 标签跨域 + 回调函数接收数据

浏览器允许`<script src="xxx">`标签跨域加载资源，不受同源策略限制，JSONP 就是利用这一点实现跨域，通过`<script>`标签`src`属性，发送带有`callback`参数的`GET`请求，服务端将接口返回数据拼凑到`callback`函数中，返回给浏览器，浏览器解析执行，从而前端拿到`callback`函数返回的数据。

流程：

1.前端定义一个回调函数

2.后端返回 **`回调函数(数据)`** 格式的 JS 代码

3.前端自动执行，拿到数据

示例：

```js
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>JSONP 跨域演示</title>
</head>
<body>

<script>
    // 1. 前端提前定义回调函数
    function handleData(data) {
        console.log("跨域成功！");
        console.log("返回数据：", data);
        alert("姓名：" + data.name + "，年龄：" + data.age);
    }
</script>
<!-- 2. 发送 JSONP 请求：把回调函数名传给后端 -->
<script src="http://localhost:8080/jsonp?callback=handleData"></script>

</body>
</html>
```

```java
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class JsonpController {

    @GetMapping("/jsonp")
    public String jsonp(
            // 接收前端传的回调函数名
            @RequestParam("callback") String callback
    ) {
        // 1. 准备数据
        String data = "{\"name\":\"张三\",\"age\":20}";

        // 2. 拼接成 JS 函数调用格式！！！【关键】
        String result = callback + "(" + data + ");";

        // 3. 返回给前端
        return result;
    }
}
```

优点：

1. **兼容性极好**：支持所有浏览器，包括非常老的 IE，是早期跨域唯一方案。
2. **实现简单**：不需要后端复杂配置，只需返回一段函数调用的 JS 代码即可。

缺点：

1. **只支持 GET 请求**：不支持 POST、PUT、DELETE。
2. **安全性较差**：若服务端被劫持，可能返回恶意代码，前端会直接执行，存在 XSS 风险。
3. **没有错误处理机制**：请求失败无法捕获异常，不能用 try/catch，也没有状态码。
4. **只支持异步，无法控制请求行为**：不像 Ajax 可以设置超时、取消请求等。
